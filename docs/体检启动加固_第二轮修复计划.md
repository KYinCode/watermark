### 任务 4:下载健壮性——`dl()` 断点续传 + **torch 走 pip 的断点续传** + 代理问询单次运行内存共享

- **`dl()`(ffmpeg zip 与 wam 权重)支持 HTTP Range 续传**:已有 `.part` 且服务器支持时从断点继续;不支持 Range 的源退回全量下载。**连接中断类重试(续传)最多 5 次**,与给 pip 定的 `--resume-retries 5` 一致(中断可续,通常能救);不支持 Range 的源退回全量下载。注意现有 `dl()` 是整包读进内存(BytesIO),大文件必须一并改成流式写盘。
- **torch(2.5GB,走 pip,不经 dl())的断点续传**:
  - pip 自 25.1 起支持 `--resume-retries N`(本机 conda env 实测 pip 26.2.1 已支持,`pip install --help` 可验证);`fix_deps()`/`robust_pip()` 调 pip 时加 `--resume-retries 5`。
  - 兼容老 pip:调用前探测 pip 版本(或捕获"unknown option"报错后去掉该参数重试);`安装环境.bat` 的 get-pip 路线装的是最新 pip,天然支持;conda 旧环境若 pip 过老可顺带 `python -m pip install -U pip`。
  - 缓存配合:`安装环境.bat` 已设 `PIP_CACHE_DIR=%ROOT%\runtime\pip_cache`(项目内),**完整**下载的 wheel 重跑命中缓存不再下载;中断的部分下载只有加 `--resume-retries` 才能续。torch 的两条源(download.pytorch.org、阿里云 pytorch-wheels 镜像)都是静态文件服务,支持 Range。
  - 五级保底链语义不变:换线路(直连→代理→镜像)重试时,续传缓存按 URL 生效,同 URL 断点可续。
- **代理问询单次运行内存共享**:`detect_proxy()` 探测结果与 `ask_proxy()` 问到的地址,在单次进程内缓存共享(全局变量即可),ffmpeg 下载和 pip 安装不重复问同一个代理;**不写任何文件**(用户"绝不记住"原则不变)。

### 任务 5:启动自愈链(用户方案,已采纳细化)

- 现状弱点:启动WebUI.bat `:do_start` 直接 `python webui\app.py`,依赖缺失时裸崩 `ModuleNotFoundError`,零防御。
- 方案(`webui/启动WebUI.bat` 的 `:do_start`):
  1. `"%PYEXE%" webui\app.py` 以非零码退出时,先跑**诊断性 import**:`"%PYEXE%" -c "import fastapi, uvicorn"`(约 1 秒,只在失败路径执行);
  2. 诊断失败 → 确认是依赖问题 → 询问"检测到依赖缺失,自动修复?"(回车=修复 / N=给指引)→ `"%PYEXE%" tools\env_check.py --fix` → **重试启动一次**;
  3. 诊断成功 → 不是装包能解决的(端口被抢/代码错/缺项目文件)→ 亮出原始错误输出 + 手动指引,停止;
  4. 重试仍失败 → 亮输出 + 指引,**绝不循环**(最多"修复→重试"一轮);
  5. 重试启动成功后**补开一次浏览器**(修复耗时期间原先定时打开的那个指向的是死页)。
- 已知实现权衡(新会话自行斟酌):若把 stderr 常驻重定向到临时文件,uvicorn 的警告日志就不实时可见了;失败时需要 `type` 出来。推荐:stderr 重定向到临时文件 + 失败时展示;stdout(启动横幅)保持直连控制台。
- **覆盖边界(要写进脚本注释与 README)**:app.py 本身不 import torch,torch 只在引擎子进程加载——torch 缺失**不挡启动、不触发本链**,由任务失败信息(ModuleNotFoundError: No module named 'torch')和状态页 GPU 检测暴露;torch 的"损坏自愈"已有 `torch_state()` 覆盖。
- 安全阀保持:`py_kind()=="other"`(系统 Python)时 env_check 拒绝安装,自愈链要把它转成"请先运行 webui\安装环境.bat"的可读指引,而不是静默失败。

## 三、新会话必须知道的技术事实与坑

1. **不要动 `app.py` `__main__` 的自建 Selector 循环**:`asyncio.SelectorEventLoop()` + `loop.run_until_complete(server.serve())` 是为绕开 **uvicorn≥0.36 在 Windows 把 loop_factory 写死 ProactorEventLoop、完全无视 set_event_loop_policy**(0.52.4 源码 `uvicorn/loops/asyncio.py` 实证,传 `loop="asyncio"` 也一样)。这是修"客户端断开 ConnectionResetError 带崩服务"的正确姿势,ffmpeg 检测行按交接文档要求保留。
2. **bat 三坑**:①文件必须 UTF-8 无 BOM + CRLF;②`if (...)` 块内 echo 文本含**半角括号对** `(xxx)` 会提前闭合块(报"xxx was unexpected"),一律 goto 风格或全角括号;③Git Bash 下 bat 的 `timeout` 被 GNU timeout 抢用,等待用 `ping -n N 127.0.0.1`。
3. **解析链同序约定**:Python = local_config.bat 的 WM2_PY > runtime\ > conda 常见位置;ffmpeg = WM_FFMPEG > 项目 bin\ > PATH > 常见安装位置。改动时保持两 bat / env_check / common.py / wm_env.sh 五处一致。
4. **"绝不记住"原则**:问到的代理端口不落盘(用户定的防毒配置),内存内共享允许(见任务 4)。
5. **安全阀**:`py_kind()`——只往 runtime\python 或名为 wm2 的 conda env 装,系统 Python 拒绝。
6. **端口/进程约定**:WebUI 端口 8765;启动/停止 bat 已有"tasklist 核对 python.exe 才杀"的防误杀逻辑,不要回退。
