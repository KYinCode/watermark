## 一、背景

前作(`F:\Project\blind_watermark`,DWT-DCT-SVD 传统频域水印)已交付,但实测能力边界:
仅在 1:1 抽帧 + 轻转码(crf≤14~16)内可验证;**全屏录屏(crf23)提取率 0%、局部截图 0%、缩放 0%**,
且已证伪"提高嵌入强度能救回"的路径(d1 翻倍仍≈0)。

甲方(用户)的硬需求是:**别人录屏、截屏、裁剪传播后,仍能取证提取水印**。这是本项目的存在理由。

## 三、验收标准(量化,全部实测说话)

| # | 项目 | 标准 |
|---|---|---|
| 1 | 逐帧嵌入 | 每一帧都带水印,无一帧例外 |
| 2 | 画质 | 肉眼不可感知;PSNR 抽样 ≥36dB(对标前作 36.4dB 档) |
| 3 | **1:1 抽帧** | 全片抽样提取率 ≥95% |
| 4 | **抗录屏(核心)** | 全屏 1:1 录屏链路(原尺寸重编码 h264 crf23 yuv420p)后提取率 ≥80% |
| 5 | **抗局部截图(核心)** | 从画面随机裁剪 ≥25% 面积的区域(含缩放),解码成功率 ≥80%(允许定位+解码两步式);含旋转 5°/15°/60° 与**水平镜像** |
| 6 | 抗转码/降清/多代 | 等分辨率二压(crf18~23)≥80%;**降清转码 720p**(还原 1080p 或多分辨率直接解码)≥80%,540p 实测报告;**连续 2 代转码** ≥60%;帧率 60→30fps 不得明显低于 1:1 基线;微信级高压(crf28 级 720p)实测报告 |
| 7 | **抗画面合成/拼接(核心)** | 搬运包边场景:原画面等比缩放至 70%~90% 置入新画布(周围为纯色/模糊背景或无水印的其他画面)并重编码(crf18),可自动定位含水印区域并解码,成功率 ≥80%;画中画/贴片场景:画面某 ≥25% 区域被其他画面覆盖或替换,剩余含水印区域仍可定位+解码(≥80%) |
| 8 | 抗常规画质攻击 | 椒盐噪声 5%、高斯模糊、亮度 ±10%、随机遮挡 10%、**滤镜调色(对比度/饱和度/色相 ±20%)** 各单项解码率 ≥80%(600 帧连续段实测) |
| 9 | 抗组合搬运流程 | 搬运号标准"一条龙":水平镜像+裁切+滤镜调色+降清转码+角标贴片,组合后解码率 ≥60% |
| 10 | 手机翻拍屏幕(尽力项) | 翻拍链路(手机拍屏幕:透视畸变+摩尔纹+白平衡偏移)实测并如实报告数据,不设硬门槛 |
| 11 | 嵌入耗时 | RTX 4060 Laptop 8GB 上全片 ≤2 小时 |
| 12 | 提取易用性 | 提供:单帧图片提取脚本 + 按时间点从视频抽帧提取的工具(或 web 集成方案建议);单帧解码失败时支持 ±0.5s 邻域自动重试 |
| 13 | 图片 | 2 张源图同样打水印;1:1 读取可解码,局部截图(≥25% 面积)可解码 |
| 14 | 成品规格 | 与源视频同规格(1920×1080 60fps 22478 帧,音轨未重编码),抽帧提取工具对成品可正常工作 |

若单项选型实验无法达标,如实报告数据并给出最接近的替代方案,不要编造达标。

## 六、实验纪律(前作血泪教训,违反会得出错误结论)

1. **不要用独立单帧/16 帧小片测编码鲁棒性**:x264 连续编码的 P 帧参考链行为与独立编码完全不同(独立 1/16 vs 连续 98/100)。任何"过编码"实验必须用 **≥600 帧连续段**。
2. 结论以实测为准,不要引用论文/README 声称的鲁棒性数字作为达标依据。
3. 显存/耗时数据先小样再外推全片。

## 八、边界与不做的事

- 不要求抵抗针对性的 AI 去水印模型/对抗攻击;覆盖范围:录屏、截屏、画面合成(包边/画中画/贴片)、平台转码(含降清/多代/帧率变化)、镜像、滤镜调色、组合搬运流程、日常传播。时间轴上的段落级拼接(替换某些秒的内容)不在范围内——被整段替换的帧本身不含水印,无法也不需要防御。
- 不改动前作交付物(`F:\Project\blind_watermark\DeepSeek+DSH\` 下成品与 README 保持原样)。
- 方案细节(模型、编码格式、管线架构)由你自行调研决定,但关键取舍(选型变更、画质档位、预计耗时超标)需向用户汇报确认后再全片执行。
