# watermark-v2 WebUI 需求文档

> 版本:v1.0(2026-09-05)
> 本文档只定义**功能需求与约束**,不约定任何页面风格、视觉设计、布局与交互美学——这些由设计会话全权决定。
> 技术约束:后端限 Python;前端框架、后端微框架(FastAPI/Flask 等)由实现方在 Python 生态内自选。

---

## 1. 背景与目标

底层引擎(本仓库)已实现基于 WAM 的学习型水印:

- **嵌入**:对视频逐帧、图片整幅嵌入 32-bit 水印 ID,抗录屏/截图裁剪/画面合成/平台转码(验收数据见 `docs/验收报告.md`);
- **提取**:对任意可疑图片/视频做取证提取,内置两步式策略链(镜像、亮度/色相反补偿、定位框、多窗、角度搜索)。

WebUI 的目标:**把"打水印"和"查水印"两件事从命令行搬进浏览器**,让非命令行场景(日常出稿后批量打水印、发现搬运后快速取证)可以自助完成。

## 2. 用户与部署(已确认)

| 项 | 结论 |
|---|---|
| 部署位置 | 本机(localhost),不暴露公网 |
| 用户 | 单人(版权所有者本人),**无账号/登录体系** |
| 并发 | 单用户,但 GPU 任务必须**串行排队**(见 §6 引擎约束) |

## 3. 核心概念(实现方必读)

- **作品(Work)**:一段版权文本 + 由它派生的水印 ID。`ID = SHA-256(版权文本 UTF-8) 前 4 字节(大端)`,32 bit。
  例:现有作品 ID `96e6955d` ↔ 文本 `©Yin(Yin_Code/KYin_Code/KYin)版权所有|禁止搬运 Bili:3706940936948128 Douyin:Yin_Code`。
- **码本(Codebook)**:ID ↔ 版权文本的登记表。提取端靠查码本把 ID 还原成文本。当前为单文件 JSON(`tools/codebook.json`),WebUI 需将其升级为可管理的数据存储(格式自定,但必须保持提取兼容,见 R1.5)。
- **派生规则不可变**:ID 派生算法必须与现有引擎完全一致,否则已发布的成品视频将无法提取。码本迁移时,已有作品(96e6955d)的 ID 不得重算变化。

## 4. 功能需求

优先级:P0 必须 / P1 应该 / P2 可选(可放入后续版本)。

### F1 作品与码本管理(P0)

- R1.1 作品列表:展示名称、版权文本、ID(hex)、创建时间、已用于几个成品。
- R1.2 新建作品:输入名称 + 版权文本,系统按 §3 规则自动派生 ID 并入库;不允许手填 ID。
- R1.3 编辑:仅允许改名称/备注;**版权文本不可改**(改文本=改 ID,应引导新建作品)。
- R1.4 删除:需二次确认,并明确提示"已用该 ID 打水印的存量成品仍可提取,但删除后新提取将显示'未知 ID'"。
- R1.5 **提取兼容**:码本变更后,命令行工具 `tools/extract_wm.py` 与 WebUI 提取功能必须基于同一份存储,且多 ID 查表(现有引擎按单 ID 编写,此为需要同步完成的引擎改造点)。
- R1.6 迁移:首次启动时自动导入现有 `tools/codebook.json` 的 96e6955d 条目。
- R1.7 ID 冲突检测:新建时若派生 ID 与已有作品重复(概率极低),拒绝并提示。

### F2 打水印(嵌入任务,P0)

- R2.1 素材来源两种:
  - **本机路径**:浏览/填写本机文件路径(推荐,免上传);
  - **上传**:浏览器上传至 `data\`(见 R5.2 大文件要求)。
  支持视频(mp4/mov/mkv/avi/flv/webm)与图片(png/jpg/jpeg)。
- R2.2 参数:选择作品(→决定嵌入哪个 ID)、视频画质 crf(默认 14)、**嵌入强度(水印强度)**:
  - 引擎参数 scaling_w,控制水印残差幅度:**越大越鲁棒、画质(PSNR)越低;越小越隐形、越不耐攻击**;
  - 必须提供 预设档 + 自定义数值(1.0~4.0,步进 0.1):
    | 预设 | 视频值 | 图片值 | 适用场景(实测依据) |
    |---|---|---|---|
    | 隐形优先 | 1.5 | 2.0 | 画质极致,接受鲁棒性下降,需自行评估 |
    | 标准(默认) | 2.0 | 2.5 | 全部验收项达标的档位(视频 PSNR 37.9~40.3 / 图片 36.5~36.8) |
    | 鲁棒优先 | 3.0 | 3.0 | 组合搬运等严苛场景;代价 PSNR 降至约 35(低于 36 达标线) |
  - 强度与画质的关系实测为:相对标准档,PSNR 变化 ≈ -20·log10(强度/2.0) dB(2.0→2.5 约 -1.9dB,2.0→3.0 约 -3.5dB);
  - 界面在选档时展示上述预估影响;提取端为盲提取,**不感知强度**,改强度不影响已有提取兼容性;
  - 同一作品的不同成品可用不同强度,码本不变。
- R2.3 任务队列:GPU 任务**串行执行**(同卡不允许并发嵌入),队列可见(排队中/运行中/完成/失败/已取消)。
- R2.4 进度:嵌入为长任务(实测 1080p60 约 46ms/帧,6 分钟视频约 20 分钟),必须实时展示 已处理帧数/总帧数、百分比、预计剩余时间;进度数据来自引擎逐批处理计数。
- R2.5 取消:运行中任务可取消,终止子进程并清理半成品文件。
- R2.6 完成后自动自检:对成品抽样(视频抽 1 帧、图片直接)执行提取,自检结果(命中/未命中)展示在任务详情中。
- R2.7 批量:多张图片一次提交为一个批量任务;多个视频逐个排队。
- R2.8 失败处理:任务失败(如 ffprobe 无法读取、显存不足)时给出可读原因,不产生半成品成品文件。
- R2.9 命名与产物:产物固定写到 `output\`,命名 `<源文件名>_已加水印.mp4/.png`,meta(JSON)同名;此约定与现有 CLI 一致。

### F3 查水印(提取/取证,P0)

- R3.1 待检素材来源:上传文件 或 本机路径(本机自用场景,大视频走路径可免除上传)。
- R3.2 图片提取:
  - 输出:命中(展示完整版权文本、作品名、ID、命中策略名)/ 未知 ID(给出 ID 值)/ 未检出;
  - 展示该次的策略链尝试信息(工具已有,如 "策略=full");
  - 耗时要求:常规命中 ≤5 秒出结果(引擎单帧含策略链最坏约 1~2 秒)。
- R3.3 视频时间点提取:
  - 输入:视频 + 时间点(秒或 hh:mm:ss,可手输可拖动定位)+ 邻域窗口(默认 ±0.5s,可调 0~5s);
  - 引擎在邻域内逐帧执行策略链并做多数投票;
  - 输出:版权文本(或未检出)、命中帧数/总帧数、策略分布;耗时要求 ≤30 秒(60 帧邻域)。
- R3.4 结果留存:每次提取保存记录(时间、待检文件名、结果、参数),可查看历史;支持一键复制版权文本、导出单次取证 JSON(供留证)。
- R3.5 视频全片扫描(P2):按可配置间隔(默认 5s)抽样提取,输出时间轴命中分布(哪些时间段含本方水印)。
- R3.6 大文件:上传通道须支持 ≥2GB 视频(分块上传或流式);若用"本机路径"方式则无此限制。

### F4 成品库与历史(P1)

- R4.1 成品列表:浏览 `output\` 下的成品(名称、规格、大小、时间),支持下载、在系统默认播放器/看图器打开。
- R4.2 嵌入任务历史与提取历史分开展示,保留失败/取消记录。

### F5 系统状态(P1)

- R5.1 自检面板:GPU 可用性与显存、torch CUDA、ffmpeg 可达、模型权重存在、码本条目数、当前队列状态。
- R5.2 存储水位:`data\` 与 `output\` 所在盘剩余空间。

### F6 引擎侧配套改造(随本 WebUI 交付,均为 P0)

- R6.1 嵌入接口参数化:支持"传入作品文本 → 派生 ID → 嵌入"(现为写死单 ID)。
- R6.2 提取查表多 ID 化:`tools/extract_wm.py` 与引擎共用 WebUI 的码本存储,支持多 ID 命中与"未知 ID"输出。
- R6.3 任务化封装:嵌入/提取以可取消子进程方式运行,标准输出按行解析为进度事件。
- R6.4 兼容回归:改造完成后,对现有成品 `output/DeepSeek+DSH_已加水印_v2.mp4` 抽帧提取必须仍命中 96e6955d。

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 运行环境 | Windows,conda 环境 wm2(Python 3.10 + torch 2.5.1+cu124),NVIDIA GPU(实测 RTX 4060 Laptop 8GB),ffmpeg 位于 `C:\Environment\FFmpeg\FFmpeg_Builds\bin\` |
| 监听 | 默认仅绑定 127.0.0.1;如改绑局域网须在界面上有明显提示(无鉴权) |
| GPU 串行 | 任何时刻最多 1 个 GPU 任务;排队由后端队列保证,禁止并发调用引擎(并发会触发 Windows WDDM 显存倒腾,导致整机卡死) |
| 显存 | 单任务峰值约 2.5GB,须保留 GPU 显存护栏机制(现有引擎已内置 45% 上限) |
| 可靠性 | 后端重启后:码本与历史记录不丢失;运行中任务标记为"中断"(允许重新排队),不产生半成品 |
| 日志 | 每个任务独立日志,UI 可查看;失败时能定位到具体报错行 |
| 数据迁移 | 首次启动自动迁移现有 `tools/codebook.json` 与既有成品记录 |
| 浏览器 | 现代桌面浏览器(Chrome/Edge)即可,无需兼容移动端 |

## 6. 引擎事实(实现方直接采用,勿重新推导)

以下为底层引擎实测结论,设计任务量与交互时以此为据:

| 事实 | 数值 |
|---|---|
| 嵌入耗时 | 1080p60 实测约 46ms/帧(含编码);6 分钟视频约 20 分钟;纯 GPU 嵌入 30ms/帧 |
| 单帧提取 | 直解约 40ms;策略链最坏约 35 次尝试 ≈ 1~2 秒/帧 |
| 视频邻域提取 | ±0.5s = 61 帧,典型 3~30 秒/次 |
| 嵌入显存 | 峰值约 2.5GiB(1080p,批量 8) |
| 提取判定 | 32bit 全对才算"命中";码本未登记的 ID 输出"未知 ID" |
| 成品规格 | 视频输出 h264 yuv420p + 音轨原样 copy,帧数与源一致(引擎末尾自动校验) |
| 已知边界 | 整段替换的内容不含水印不可防;组合搬运在 UI 录屏类内容未达标;手机翻拍未保证(详见验收报告第 5 节) |

## 7. 明确不做(本期范围外)

- 账号、多用户、权限、公网部署、HTTPS;
- GPU 多任务并行;
- 在线视频播放器的高级功能(预览以"能确认内容"为限);
- 对抗 AI 去水印/对抗攻击的任何能力;
- 手机翻拍链路的专项处理。

## 8. 验收要点(WebUI 自身的完成定义)

1. 新建作品 → 用该作品对一段测试视频打水印 → 完成后自检提取命中该作品文本;
2. 上传 386MB 级视频(或用本机路径)创建嵌入任务,进度实时更新且完成后成品落盘可下载;
3. 对一张截图执行提取,≤5 秒内返回结果并可一键复制文本;
4. 对成品视频某时间点提取,≤30 秒返回,历史记录可查;
5. 删除一个测试作品后,含该 ID 的存量成品提取结果显示"未知 ID"并给出 ID 值;
6. 重启后端服务,码本、历史记录、队列状态符合 §5 可靠性要求;
7. 现有成品(96e6955d)提取回归通过(R6.4)。
